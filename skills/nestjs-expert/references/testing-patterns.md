# Testing Patterns

Runner: Jest in CommonJS projects, Vitest in ESM projects generated by NestJS 12. The API below is the same; swap `jest.fn()` for `vi.fn()` and `jest-mock-extended` for `vitest-mock-extended`. Vitest needs SWC (`unplugin-swc`) so decorators emit metadata.

## Two layers

| Layer | Database | Checks |
|-------|----------|--------|
| Unit (service) | Mocked `PrismaService` | Branching, error mapping, what gets passed to Prisma |
| E2E (HTTP) | **Real** PostgreSQL (Docker/Testcontainers), migrated with `prisma migrate deploy` | Validation, guards, status codes, response shape, constraints |

Mocks can't catch a wrong `where`, a missing index or a unique violation. Anything that depends on the database belongs in E2E.

## Unit: service with a mocked Prisma

```typescript
import { Test } from '@nestjs/testing';
import { NotFoundException, ConflictException } from '@nestjs/common';
import { mockDeep, DeepMockProxy } from 'jest-mock-extended';
import { PrismaService } from '../prisma/prisma.service';
import { Prisma } from '../generated/prisma/client';
import { UsersService } from './users.service';

describe('UsersService', () => {
  let service: UsersService;
  let prisma: DeepMockProxy<PrismaService>;

  beforeEach(async () => {
    const module = await Test.createTestingModule({
      providers: [UsersService, { provide: PrismaService, useValue: mockDeep<PrismaService>() }],
    }).compile();

    service = module.get(UsersService);
    prisma = module.get(PrismaService);
  });

  it('throws NotFoundException when the user does not exist', async () => {
    prisma.user.findUnique.mockResolvedValue(null);
    await expect(service.findOne('u1')).rejects.toThrow(NotFoundException);
  });

  it('maps a duplicate email (P2002) to 409', async () => {
    prisma.user.create.mockRejectedValue(
      new Prisma.PrismaClientKnownRequestError('Unique constraint', { code: 'P2002', clientVersion: 'test' }),
    );
    await expect(
      service.create({ email: 'a@b.com', name: 'A', password: '<test-password>' }),
    ).rejects.toThrow(ConflictException);
  });

  it('never selects the password hash', async () => {
    prisma.user.findUnique.mockResolvedValue({ id: 'u1', email: 'a@b.com' } as never);
    await service.findOne('u1');
    expect(prisma.user.findUnique.mock.calls[0][0].select).not.toHaveProperty('passwordHash');
  });
});
```

`$transaction` with a callback: `prisma.$transaction.mockImplementation((fn) => fn(prisma))` so the callback receives the same mock.

## Controller tests

Usually redundant with E2E. Write them only when the controller has logic of its own (mapping, headers, streaming): mock the service with `{ provide: UsersService, useValue: { findOne: jest.fn() } }`.

## E2E: real app, real database

```typescript
import { Test } from '@nestjs/testing';
import { INestApplication, ValidationPipe } from '@nestjs/common';
import request from 'supertest';
import { AppModule } from '../src/app.module';
import { PrismaService } from '../src/prisma/prisma.service';

describe('Users (e2e)', () => {
  let app: INestApplication;
  let prisma: PrismaService;

  beforeAll(async () => {
    const moduleRef = await Test.createTestingModule({ imports: [AppModule] }).compile();
    app = moduleRef.createNestApplication();
    configureApp(app); // the same function main.ts uses: pipes, filters, prefix, versioning
    await app.init();
    prisma = app.get(PrismaService);
  });

  beforeEach(async () => {
    // Order matters for foreign keys, or use TRUNCATE ... CASCADE
    await prisma.$executeRaw`TRUNCATE "Post", "User" CASCADE`;
  });

  afterAll(() => app.close());

  it('POST /users creates and hides the hash', async () => {
    const res = await request(app.getHttpServer())
      .post('/users')
      .send({ email: 'new@test.com', name: 'New', password: '<test-password>' })
      .expect(201);
    expect(res.body).not.toHaveProperty('passwordHash');
  });

  it('POST /users rejects a duplicate email with 409', async () => {
    const body = { email: 'dup@test.com', name: 'Dup', password: '<test-password>' };
    await request(app.getHttpServer()).post('/users').send(body).expect(201);
    await request(app.getHttpServer()).post('/users').send(body).expect(409);
  });

  it('POST /users rejects unknown fields with 400', () =>
    request(app.getHttpServer())
      .post('/users')
      .send({ email: 'x@test.com', name: 'X', password: '<test-password>', role: 'ADMIN' })
      .expect(400));
});
```

- Export a `configureApp(app)` from `main.ts` (or a sibling file) so tests run with the same global pipes, filters and prefix as production. Re-declaring `useGlobalPipes` in tests drifts.
- Point `DATABASE_URL` at a dedicated test database (`.env.test`). Never at dev or production data.
- Run E2E files serially (`--runInBand` in Jest, `fileParallelism: false` in Vitest) when they share one database.
- Per route, cover: happy path, 400 (validation), 401/403 (auth), 404, and 409 where a unique constraint exists.

## Quick Reference

| Pattern | Use |
|---------|-----|
| `Test.createTestingModule()` | Build a module for the test |
| `mockDeep<PrismaService>()` | Typed Prisma mock |
| `.overrideProvider(X).useValue(...)` | Replace one provider in an E2E module (e.g. mail, payments) |
| `request(app.getHttpServer())` | HTTP calls with supertest |
